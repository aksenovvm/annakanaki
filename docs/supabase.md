# Подключаем базу данных Supabase (этап 3)

Код базы уже готов: таблицы описаны в `packages/db/prisma/schema.prisma`, миграция и тестовые данные тоже есть.
Осталось создать саму базу в облаке и сказать проекту, как к ней подключиться.

Займёт ~15 минут.

---

## Шаг 1. Создаём проект в Supabase

1. Откройте **https://supabase.com** → **Start your project** → войдите через GitHub.
2. Нажмите **New project**.
3. Заполните:
   - **Name** — `barbershop`;
   - **Database Password** — нажмите **Generate a password**, затем **Copy**.
     ⚠️ Сохраните пароль (например, в заметки) — он понадобится на шаге 2 и больше нигде не показывается;
   - **Region** — ближайший к Ташкенту: **Central EU (Frankfurt)**.
4. Нажмите **Create new project** и подождите 1–2 минуты, пока проект создаётся.

## Шаг 2. Копируем строки подключения

1. В проекте нажмите кнопку **Connect** вверху страницы.
2. Откройте вкладку **ORMs** и выберите **Prisma**.
3. Вы увидите две строки: `DATABASE_URL` и `DIRECT_URL`.

Теперь в VS Code:

1. В списке файлов слева откройте папку `packages/db`.
2. Нажмите правой кнопкой на файл `.env.example` → **Copy**, потом правой кнопкой на папку `db` → **Paste**.
3. Переименуйте копию в **`.env`** (правая кнопка → **Rename**).
4. Откройте `.env` и замените обе строки на те, что показал Supabase.
5. В обеих строках замените `[YOUR-PASSWORD]` на пароль из шага 1 (квадратные скобки тоже убрать).
6. Сохраните файл: **Ctrl + S** (Mac — **Cmd + S**).

> Файл `.env` содержит пароль, поэтому он **не** попадает в GitHub — это настроено в `.gitignore`.

## Шаг 3. Создаём таблицы и тестовые данные

В терминале VS Code (**Terminal → New Terminal**) по очереди:

```bash
npm install
npm run db:deploy
npm run db:seed
```

- `db:deploy` — создаёт в Supabase все 13 таблиц (применяет миграцию);
- `db:seed` — добавляет услуги, барберов, график, настройки и 4 отзыва.

В конце должно появиться:

```text
Тестовые данные добавлены:
  услуг: 6
  барберов: 4
  ...
```

## Шаг 4. Проверяем

**Через терминал:**

```bash
npm run db:check
```

Покажет услуги, барберов с графиком и обедами, исключения и настройки.

**Через Supabase:** слева **Table Editor** → таблицы `services`, `barbers`, `working_hours`, `settings`…

**Через Prisma Studio** (удобная «таблица» в браузере):

```bash
npm run db:studio
```

## Шаг 5. Ключи для хранилища фото (понадобятся на этапе 4+)

В Supabase: **Project Settings** (шестерёнка слева) → **API Keys**.

- **Project URL** — это будет `SUPABASE_URL`;
- **secret** ключ (в старых проектах называется **service_role**) — это `SUPABASE_SERVICE_ROLE_KEY`.

⚠️ Секретный ключ даёт полный доступ к проекту. Никогда не вставляйте его в код сайта и не отправляйте в чат.
Пока просто сохраните оба значения в заметки — на этапе 4 они пойдут в `apps/api/.env`.

## Полезные команды

| Команда | Что делает |
|---|---|
| `npm run db:deploy` | применить миграции к базе |
| `npm run db:seed` | заполнить **пустую** базу тестовыми данными |
| `npm run db:check` | показать, что лежит в базе |
| `npm run db:studio` | открыть базу в браузере |
| `npm run db:migrate` | после изменения `schema.prisma` — создать новую миграцию |
| `npm run db:reset` | ⚠️ удалить **все** данные и создать базу заново |

## Если что-то не так

| Ошибка | Что делать |
|---|---|
| `password authentication failed` | неверный пароль в `.env`. Можно сбросить: **Project Settings → Database → Reset database password** |
| `Can't reach database server` | проверьте интернет; проверьте, что строки скопированы целиком |
| `DATABASE_URL не задан` | файл должен называться ровно `.env` и лежать в `packages/db` |
| `seed пропущен` | база уже заполнена — это нормально |

## Как устроена база

- **13 таблиц** — как в `docs/spec.md`, раздел 5.
- Все id — UUID, все даты — `timestamptz` (UTC), показываем в `Asia/Tashkent`.
- Цены — целые числа в сумах.
- Дни недели: **1 = понедельник … 7 = воскресенье**.
- Проверки прямо в базе: рейтинг 1–5, конец позже начала, цена ≥ 0 и т.д.
- **RLS включён** на всех таблицах: через публичные ключи Supabase к данным не достучаться. Работает с ними только наш backend.
- Защита от двойной записи (`bookings_no_overlap`) появится на этапе 5.
