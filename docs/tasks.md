# TASKS: поэтапная сборка учебного проекта

Главный принцип:

> После каждого этапа проект запускается, а студент видит новый законченный результат.

Не нужно просить AI-агента реализовать весь проект одним запросом.

Работа идёт по этапам.

- Сайт: главная и `/book` получают услуги, барберов и отзывы из API при каждом открытии страницы;

## Статус: ✅ выполнен

Backend (`apps/api`):

- Расчёт свободного времени — чистые функции в `src/domain/availability.ts`:
  рабочие часы, обеды, `time_off` (мастера и всего барбершопа), существующие записи, шаг `slot_step_min`,
  `min_notice_min`, `booking_horizon_days`, длительность с учётом своих цен/длительностей мастера.
- `GET /api/v1/availability` и `GET /api/v1/availability/days` (сколько слотов в каждом дне — для календаря).
- `POST /api/v1/bookings`: Zod → услуги → мастер → цена и длительность → расписание → исключения →
  актуальная доступность → транзакция. Ответы: `201`, `409 SLOT_TAKEN`, `422 OUTSIDE_WORKING_HOURS / TOO_SOON / TOO_FAR`, `400`.
- `barberId=any`: объединённые слоты; при записи — наименее загруженный свободный мастер,
  если его успели занять — следующий.
- `GET /bookings/:token`, `POST /bookings/:token/cancel`, `POST /bookings/:token/reschedule`
  (лимит `cancel_cutoff_min`, `422 TOO_LATE_TO_CHANGE`, `409 BOOKING_NOT_ACTIVE`).

База (`packages/db`): миграция `*_booking_no_overlap` — `btree_gist`, generated `time_range`,
exclusion constraint `bookings_no_overlap`; ошибка `23P01` → `409 SLOT_TAKEN`.

Сайт (`apps/web`):

- Шаг «Дата и время» берёт дни и слоты из API, дни без мест выключены.
- Запись сохраняется в базу и открывает страницу `/booking/[token]`: детали, статус, копирование ссылки,
  перенос (выбор нового времени) и отмена с подтверждением.
- `SLOT_TAKEN` → «Это время только что заняли» и возврат к выбору времени.
- Тестовый `mockApi.ts` удалён.

Тесты:

- `npm test` — 23 unit-теста слотов (обед, конец дня, исключения, длительности, min notice, горизонт, «любой», cutoff).
- `npm run test:integration` — 11 тестов с настоящей базой, включая обязательный:
  **два параллельных запроса на один слот дают ровно один `201` и один `409`**.
